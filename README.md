# Internet Speed Test

Небольшая консольная утилита на Node.js для измерения скорости загрузки данных с указанного URL.

Скрипт последовательно выполняет 10 HTTP-запросов, полностью считывает тело каждого ответа и выводит сводную статистику.

## Возможности

- Принимает URL в качестве аргумента командной строки.
- Выполняет 10 последовательных запросов к указанному адресу.
- Дожидается полной загрузки тела каждого ответа.
- Измеряет время каждого запроса.
- Рассчитывает среднее время запроса.
- Суммирует объём загруженных данных.
- Рассчитывает среднюю скорость загрузки.
- Проверяет URL и обрабатывает сетевые ошибки и тайм-ауты.

## Требования

- Node.js версии 18.17.0 или новее.
- npm (поставляется вместе с Node.js).

Внешние npm-зависимости не требуются: используются встроенные возможности Node.js (`fetch`, `URL`, `AbortSignal.timeout` и `node:perf_hooks`).

## Запуск

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/<your-username>/internet-speed-test.git
   ```

2. Перейдите в папку проекта:

   ```bash
   cd internet-speed-test
   ```

3. Запустите тест, передав URL:

   ```bash
   npm start -- 'https://speed.cloudflare.com/__down?bytes=1000000'
   ```

Для первой проверки можно использовать endpoint Cloudflare: `https://speed.cloudflare.com/__down?bytes=1000000`. Он предназначен для выдачи тестовых данных. В качестве альтернативы укажите любой доступный URL, который возвращает успешный HTTP-ответ с телом. Адрес `https://example.com/image.jpg` использовать не нужно: это условный пример, по которому файл не существует.

Если аргумент не указан, скрипт выведет подсказку по использованию.

## Единицы измерения и методика

Скорость выводится в **Мбит/с (Mbps)**, где 1 Мбит = 1 000 000 бит.

Расчёт:

```text
Скорость (Мбит/с) =
  общий объём данных (байт) × 8
  / суммарное время запросов (секунды)
  / 1 000 000
```

Среднее время запроса — сумма времени выполнения всех запросов, делённая на их количество.

Время каждого запроса измеряется от начала `fetch` до полного чтения тела ответа. Поэтому в измерение входит не только ожидание HTTP-заголовков, но и загрузка содержимого ответа.

Объём данных берётся из размера прочитанного тела ответа (`ArrayBuffer.byteLength`). Это размер тела после автоматической обработки HTTP-сжатия средствами `fetch`, а не точное количество байтов, переданных по сети на транспортном уровне.

Запросы выполняются строго последовательно: следующий начинается только после полного завершения предыдущего.

## Обработка ошибок

- Некорректный URL и неподдерживаемая схема адреса приводят к понятному сообщению об ошибке.
- Для каждого запроса установлен тайм-аут 30 секунд.
- Если сервер возвращает HTTP-статус вне диапазона успешных ответов, тест завершается с сообщением об ошибке.
- При сетевой ошибке тест прекращается, а процесс завершается с ненулевым кодом.

## Ограничения измерения

Результат характеризует скорость загрузки данных именно с выбранного сервера в условиях текущего сетевого соединения. На него могут влиять производительность сервера, географическое расположение, кэширование, ограничения частоты запросов и другие факторы. Это не универсальная оценка максимальной пропускной способности интернет-канала.
